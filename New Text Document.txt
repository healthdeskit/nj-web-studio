## Summary

For this project, the strongest fit is an **Astro-based static marketing site** deployed as a **Render Static Site** from **GitHub**, with **Tailwind CSS** for the design system. That matches your use case well because Astro is built for content-heavy, fast websites and supports static prerendering by default, while Render officially supports GitHub-connected static-site deploys with auto-deploys, global CDN, TLS, and custom domains. Tailwind’s current Astro guide also supports a direct Vite-based setup. ([Render][1])

## Evidence

Render’s official docs state that Static Sites deploy from Git repos and are served over a global CDN with automatic TLS and custom domains, and Render’s GitHub integration supports deploys on every push and preview environments for pull requests. Astro’s official Render deployment guide documents deploying an Astro site to Render as a Static Site from GitHub or GitLab. ([Render][1])

Astro’s docs state that pages are prerendered statically by default unless you opt into on-demand rendering. For a lead-generation local SEO site, that is usually the right architecture because it keeps performance high and complexity low. Tailwind’s official Astro install guide shows the current supported integration path through Vite. ([Astro Docs][2])

## Caveats

I cannot confirm this is the single best stack for every future requirement. If you later need a heavy authenticated dashboard, account portal, or app-like workflows, the architecture may need to expand beyond a pure static marketing-site approach.
